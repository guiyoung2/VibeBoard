## 2. 공통 컴포넌트 추출 (우선 적용 권장)

### 2-1. StarRating (평점 UI)

**위치:** `src/components/StarRating.tsx` (신규)

**역할**
- **표시 모드**: `value={3}` → ⭐⭐⭐ 표시

**사용처**

- `ReviewDetail.tsx` – 리뷰 상세 표시 + 수정 폼 내 평점 선택

**효과:** 평점 UI 중복 제거, 한 곳만 수정하면 됨.

### 2-2. ErrorMessageWithRetry (에러 + 다시 시도)

**위치:** `src/components/ErrorMessageWithRetry.tsx` (신규)

**props 예시**
- `message: string`
- `onRetry?: () => void`
- `retryLabel?: string` (기본 "다시 시도")
- `secondaryLink?: { to: string; label: string }` (예: 목록으로)

**사용처**

  "데이터를 불러오는 중 오류가 발생했습니다" + `refetch()` + "다시 시도" / "목록으로" 블록을 이 컴포넌트로 교체

**효과:** 에러 UI 일관성, 스타일/접근성 한 곳에서 관리.

---

### 2-3. 버튼 스타일 공통화

**방법 A (가장 간단)**  
`src/index.css`에 유틸리티 클래스 추가:

```css
.btn-primary {
  @apply px-6 py-2 rounded-lg text-white font-medium transition-colors
    disabled:opacity-50 disabled:cursor-not-allowed;
}
/* 다크 모드는 Tailwind dark: 로 처리하거나, 테마 변수 사용 */
```

그리고 Tailwind에서 `bg-primary` / `dark:bg-accent` 등으로 테마별 색만 지정.

**방법 B**  
`src/components/Button.tsx` 같은 공통 버튼을 두고  
`variant="primary" | "outline" | "danger"` 등으로 스타일 분리.

**사용처:** Login, ReviewCreate, ReviewDetail, Cafes, Profile, Layout 등  
`isDark ? "bg-accent ..." : "bg-primary ..."` 가 반복되는 모든 버튼.

**효과:** 테마 변경 시 한 곳만 수정, 가독성 향상.

## 3. ReviewDetail.tsx 분리 (819줄 → 여러 컴포넌트)

**목표:** 한 파일에 몰려 있는 “리뷰 영역”과 “댓글 영역”을 컴포넌트로 나누기.

### 3-1. 추출할 UI 블록

| 컴포넌트 | 담당 | 비고 |
|----------|------|------|
| **ReviewDetailHeader** | 작성자 아바타·닉네임·날짜·평점(StarRating) | 리뷰 상단 카드 |
| **ReviewContent** | 리뷰 본문 보기 모드 + 수정 모드(폼) | 수정/삭제 버튼은 props로 전달하거나 상위에서 렌더 |
| **CommentSection** | "댓글 (n)" 제목 + 댓글 작성 폼 + 댓글 목록 컨테이너 | |
| **CommentForm** | textarea + 제출 버튼 + 에러 메시지 | 로그인 유도는 상위에서 분기 |
| **CommentItem** | 댓글 하나 (작성자·날짜·내용·수정/삭제·인라인 수정 폼) | editingCommentId 등은 props |

### 3-2. 데이터/뮤테이션

- **쿼리**: `useQuery(["review", id])`, `useQuery(["comments", id])` 는 **ReviewDetail 페이지**에 그대로 두고,  
  `review`, `comments`, `refetch` 등을 props로 내려주는 방식이 단순합니다.
- **뮤테이션**: 리뷰 수정/삭제, 댓글 작성/수정/삭제도 페이지에 두고,  
  핸들러만 `ReviewContent` / `CommentForm` / `CommentItem`에 props로 전달하면 됩니다.

### 3-3. 적용 순서 제안

1. **StarRating** 먼저 만들고 ReviewDetail·ReviewCreate에 적용  
2. **ReviewDetailHeader** → **ReviewContent** 순으로 분리  
3. **CommentForm** → **CommentItem** → **CommentSection** 순으로 분리  

이렇게 하면 ReviewDetail.tsx는 “데이터 불러오기 + 상태 + 조합”만 담당하고, JSX 길이가 크게 줄어듭니다.

## 6. 훅 추출

### 6-1. useIsDark (또는 useTheme)

여러 페이지에서 동일하게:

```ts
const { theme } = useThemeStore();
const isDark = theme === "dark";
```

→ `const isDark = useIsDark();` 한 줄로 쓰이도록 훅으로 분리  
(내부에서 `useThemeStore()` 사용).

**위치:** `src/hooks/useTheme.ts` 또는 `src/stores/themeStore.ts` 에서 export.

### 6-2. useInfiniteDisplay (선택)

Games와 Reviews 모두:

- `displayCount`, `setDisplayCount`
- `prevDisplayCount`, `setPrevDisplayCount`
- `loadMoreRef`
- `ITEMS_PER_PAGE` 기준으로 “더 보기” 시 갱신

이 로직을 `useInfiniteDisplay(items, { pageSize: 3 })` 처럼 훅으로 만들면  
`displayCount`, `slicedItems`, `loadMoreRef`, `hasMore`, `loadMore` 만 가져다 쓰면 됩니다.

## 7. 데이터 레이어 정리 (선택)

- **리뷰 단건**  
  ReviewDetail의 `queryFn` 안에서 review + boardgame + profile 을 수동 조인하고 있음.  
  Supabase에서 `select('*, boardgames(id,name,image_url), profiles(id,nickname)')` 처럼 한 번에 가져올 수 있으면,  
  `lib/supabase.ts` 또는 `lib/api/reviews.ts` 에 `fetchReviewById(id)` 를 두고 쿼리만 그쪽으로 옮기면 재사용·테스트가 쉬워짐.
- **리뷰 목록**  
  Reviews의 여러 단계 fetch(리뷰 → boardgames → profiles)도  
  `fetchReviewsWithDetails()` 같은 함수로 묶어두면 페이지는 `queryFn: () => fetchReviewsWithDetails()` 정도만 남게 됨.

## 9. 기타 개선

- **타입**  
  Supabase 조인 결과를 그대로 쓰는 부분은 `Review`, `Comment` 등 `types/review.ts` 와 맞춰 두면, 리팩토링 시 안전합니다.
- **상수**  
  `ITEMS_PER_PAGE`, `PAGE_SIZE`, `DEFAULT_RADIUS`, `KAKAO_KEYWORD` 등은 이미 상수로 두신 부분이 많음.  
  Cafes의 `escapeHtml` 만 `lib` 또는 `utils` 로 옮기면 됩니다.
- **접근성**  
  버튼에 `aria-label`, 로딩/에러 영역에 `role="alert"` 등만 추가해도 개선됩니다.  
  공통 컴포넌트(Button, ErrorMessageWithRetry, StarRating)를 만들 때 함께 넣기 좋습니다.

원하시면 **StarRating**이나 **ErrorMessageWithRetry**부터 실제 코드 골격을 만들어 드리겠습니다. 어떤 것부터 적용할지 알려주시면 그 순서로 구체적인 코드 예시까지 적어 드리겠습니다.
