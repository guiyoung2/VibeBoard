# 에러 처리 · 로딩 · 네트워크 기능 가이드

이 문서는 VibeBoard에 적용된 **에러 처리 및 로딩 상태 개선**, **전역 에러 바운더리**, **스켈레톤 로딩 UI**, **네트워크 오류 처리**가 무엇인지, 어떻게 확인하는지 정리한 것입니다.

---

## 1. 전역 에러 바운더리 (Global Error Boundary)

### 무엇인가요?

React 앱에서 **렌더링 중에 발생한 JavaScript 에러**를 한 곳에서 잡아서, 앱 전체가 하얀 화면으로 죽지 않도록 하는 기능입니다.

- **어디에 적용했나요?**  
  `main.tsx`에서 `<App />`을 감싸는 최상위에 `ErrorBoundary`를 두었기 때문에, **앱 전체**가 한 번에 죽지 않고, 에러가 나면 대신 “문제가 발생했습니다” 화면을 보여줍니다.
- **무슨 에러를 잡나요?**  
  컴포넌트를 **그리는 도중** 발생하는 에러(예: `undefined` 참조, 잘못된 props 사용으로 인한 예외)를 잡습니다.
- **무슨 에러를 못 잡나요?**  
  이벤트 핸들러 안의 에러(클릭 후 발생 등), `setTimeout`/`fetch` 같은 **비동기** 안에서 나는 에러는 이 바운더리로는 잡지 못합니다. (그건 각 페이지/컴포넌트에서 try-catch나 React Query의 `error`로 처리합니다.)

### 적용된 파일

- `src/components/ErrorBoundary.tsx`
  - 에러 발생 시 “문제가 발생했습니다” + **새로고침** 버튼
  - 개발 모드에서만 에러 메시지·컴포넌트 스택 표시
- `src/main.tsx`
  - `ErrorBoundary`로 `BrowserRouter`와 `App`을 감싼 구조

### 어떻게 확인하나요?

1. **개발 서버 실행**  
   `npm run dev`
2. **의도적으로 렌더 에러 내기**  
   예: `src/pages/Home.tsx` 맨 위에 아래 한 줄을 넣고 저장한 뒤 해당 페이지로 이동합니다.
   ```tsx
   throw new Error("테스트용 에러");
   ```
3. **결과**
   - 앱이 하얀 화면으로 죽지 않고
   - “문제가 발생했습니다” 문구와 **새로고침** 버튼이 보이면  
     전역 에러 바운더리가 정상 동작하는 것입니다.
4. **테스트 후**  
   위에서 넣은 `throw new Error("테스트용 에러");` 한 줄은 **반드시 제거**하세요.

## 2. 스켈레톤 로딩 UI (Skeleton Loading)

### 무엇인가요?

데이터를 **불러오는 동안** “로딩 중...” 텍스트 대신, **실제 콘텐츠 모양과 비슷한 회색 블록(스켈레톤)**을 보여주는 UI입니다.

- **왜 쓰나요?**
  - 사용자가 “어디가 로딩 중인지” 직관적으로 알 수 있고
  - 레이아웃이 흔들리지 않으며
  - 체감 속도가 더 빠르게 느껴집니다.
- **어디에 적용했나요?**  
  데이터를 서버에서 가져오는 페이지/컴포넌트의 **로딩 중일 때**만 스켈레톤을 보여주도록 했습니다.

### 적용된 위치와 모양

| 위치                            | 사용 스켈레톤                            | 보이는 모양                                       |
| ------------------------------- | ---------------------------------------- | ------------------------------------------------- |
| **게임 추천** (`/games`)        | `SkeletonGameGrid`                       | 게임 카드 그리드 형태(이미지·제목·설명·태그 자리) |
| **게임 상세** (`/games/:id`)    | `SkeletonDetail`                         | 상단 이미지 + 제목 + 본문 + 정보 칸               |
| **게임 후기 목록** (`/reviews`) | `SkeletonReviewList`                     | 리뷰 카드 여러 개(프로필·별점·내용 자리)          |
| **리뷰 상세** (`/reviews/:id`)  | `SkeletonDetail` + `SkeletonCommentList` | 리뷰 본문 + 댓글 목록 자리                        |
| **홈 히어로 슬라이더**          | `SkeletonHero`                           | 히어로 영역 비율의 큰 블록 + 하단 인디케이터 자리 |

### 어떻게 확인하나요?

1. **느린 네트워크 시뮬레이션**
   - Chrome 개발자 도구(F12) → **Network** 탭
   - **Throttling**에서 “Slow 3G” 또는 “Fast 3G” 선택
2. **페이지 이동**
   - `/games`, `/reviews` 등으로 이동하거나 새로고침
3. **결과**
   - 로딩 중일 때 **회색 블록이 깜빡이는 스켈레톤**이 잠깐 보였다가, 데이터가 오면 실제 카드/리뷰로 바뀌면 정상입니다.
4. **Supabase가 빠르면**  
   로딩이 너무 짧아 스켈레톤이 거의 안 보일 수 있습니다. Network Throttling을 켜면 더 오래 보입니다.

## 3. 에러 처리 및 로딩 상태 개선 (재시도·메시지)

### 무엇인가요?

**데이터 요청이 실패했을 때** 사용자에게

- 무슨 일이 있었는지 **메시지**로 알려주고
- **다시 시도** 버튼으로 같은 요청을 쉽게 재시도할 수 있게 한 것입니다.

- **어디에 적용했나요?**  
  `useQuery`를 쓰는 페이지들:  
  게임 목록/상세, 리뷰 목록/상세, 히어로 슬라이더  
  → `error`일 때 “데이터를 불러오는 중 오류가 발생했습니다” + **다시 시도** 버튼(`refetch`)을 보여줍니다.
- **추가 설정**  
  `main.tsx`의 `QueryClient`에
  - **retry: 2** (실패 시 최대 2번 자동 재시도)
  - **retryDelay** (1초 → 2초 → … 최대 10초까지 지수 백오프)  
    를 두어, 일시적인 네트워크 끊김에 조금 더 견디도록 했습니다.

### 적용된 파일

- `src/main.tsx` — QueryClient `defaultOptions` (retry, retryDelay)
- `src/pages/Games.tsx` — 에러 시 메시지 + “다시 시도” 버튼
- `src/pages/GameDetail.tsx` — 동일
- `src/pages/Reviews.tsx` — 동일
- `src/pages/ReviewDetail.tsx` — 동일
- `src/components/HeroSlider.tsx` — 에러 시 메시지 표시

### 어떻게 확인하나요?

**방법 A — 오프라인 말고, API를 일시적으로 막기 (추천)**

- `src/lib/supabase.ts`에서 `supabaseUrl`을 임시로 `"https://invalid-url.example.com"` 같은 잘못된 주소로 바꾼 뒤 저장
- `/games` 또는 `/reviews`로 이동(또는 새로고침)
- **본문 영역**에 “데이터를 불러오는 중 오류가 발생했습니다” + **다시 시도** 버튼이 보이면 성공
- **다시 시도** 클릭 → 여전히 잘못된 URL이면 같은 메시지
- 확인 후 **원래 Supabase URL로 되돌리고 저장**

**방법 B — 오프라인으로 요청 실패 유도**

- F12 → Network → **Offline** 선택
- `/games` 또는 `/reviews` **새로고침** (해당 페이지가 데이터를 다시 요청하게 함)
- **본문(게임/리뷰 목록이 나올 자리)**에 에러 메시지 + **다시 시도** 버튼이 보이면 성공
- Online으로 바꾼 뒤 **다시 시도** 클릭 → 데이터가 다시 불러와지면 정상

→ 이건 “**이 페이지의 데이터 요청이 실패했을 때**” 나오는 UI입니다. 아래 4번(오프라인 배너)과 **보는 위치**가 다릅니다.

## 4. 네트워크 오류 처리 (오프라인 배너)

### 무엇인가요?

사용자 기기가 **인터넷에 연결되지 않은 상태(오프라인)**일 때

- 화면 상단에 **“네트워크 연결이 끊겼습니다”** 배너를 보여주고
- **다시 온라인이 되면** React Query 캐시를 무효화해서 필요한 데이터를 다시 가져오게 하는 기능입니다.

- **어디에 적용했나요?**  
  `Layout` 상단에 `NetworkStatus` 컴포넌트를 넣어서, **모든 페이지**에서 공통으로 배너가 보이도록 했습니다.
- **동작**
  - `navigator.onLine`과 `online` / `offline` 이벤트로 오프라인 감지
  - 온라인 복귀 시 `queryClient.invalidateQueries()`로 쿼리 재요청

### 적용된 파일

- `src/components/NetworkStatus.tsx` — 오프라인 감지 및 배너
- `src/components/Layout.tsx` — `<NetworkStatus />` 렌더

### 어떻게 확인하나요?

1. **개발 서버 실행** 후 **아무 페이지나** 연다 (예: `/`, `/games`).
2. **오프라인으로 전환**
   - F12 → **Network** 탭 → **Throttling** 옆 드롭다운에서 **Offline** 선택  
     (또는 Chrome “오프라인” 모드)
3. **결과 — 여기만 보면 됨**
   - **화면 맨 위(헤더 위)** 에 빨간 배너로  
     **“네트워크 연결이 끊겼습니다. 연결을 확인한 뒤 다시 시도해 주세요.”** 가 보이면 정상입니다.
   - `/games`를 열었는지, `/`를 열었는지와 상관없이, **오프라인만 되면 어디서나** 이 배너가 뜹니다.
4. **다시 온라인**
   - Offline 해제 후 새로고침하거나 다른 페이지로 이동하면 데이터가 다시 불러와지면 정상입니다.

---

### 3번(에러 처리·재시도)이랑 4번(네트워크 오류 처리) 차이 — Offline으로 둘 다 볼 때

둘 다 **F12 → Network → Offline** 으로 “네트워크 끊김”을 만들 수는 있습니다.  
하지만 **확인하는 UI가 다릅니다.**

| 구분               | 3. 에러 처리·로딩 개선 (재시도)                                                                                | 4. 네트워크 오류 처리 (배너)                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **뭘 보나요?**     | **페이지 본문** — 게임/리뷰 목록이 나올 자리에 “데이터를 불러오는 중 오류가 발생했습니다” + **다시 시도** 버튼 | **화면 맨 위** — 헤더 위에 “네트워크 연결이 끊겼습니다” **배너** |
| **언제 보이나요?** | **데이터를 요청한 페이지**(/games, /reviews 등)에서 **그 요청이 실패했을 때**                                  | **오프라인인 동안**이라면 **어느 페이지에 있든** 항상            |
| **역할**           | “이번 요청이 실패했다” + 재시도                                                                                | “지금 네트워크가 끊겼다”는 **상태 알림**                         |

그래서 Offline 한 번 걸어두고 확인할 때:

- **맨 위 배너** → 4번 네트워크 오류 처리
- **/games 또는 /reviews 본문의 에러 박스 + 다시 시도** → 3번 에러 처리·재시도

3번은 Offline 말고 **Supabase URL을 잘못 바꿔서** 확인해도 됩니다 (위 “방법 A”).
